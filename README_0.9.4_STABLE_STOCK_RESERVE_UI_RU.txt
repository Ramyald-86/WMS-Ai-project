FulfillCore 0.9.4 — стабильные WB-остатки, резерв и складской интерфейс

Основа: 0.9.3 IMMEDIATE FBS RESERVE STRICT SKU. Рабочая CHZ-логика не переписывалась.

Изменено:
1. Массовая публикация WB FBS теперь частичная: ошибочный ШК/chrtId не блокирует остальные позиции.
2. FulfillCore ставит PUBLISHED только после чтения обратно и точного подтверждения количества WB. Ошибки сохраняются по конкретным ШК.
3. В Остатках после частичного обновления доступен Excel со списком проблемных ШК/chrtId/причин.
4. Приёмка, выбранная как FulfillCore + WB FBS, продолжает отправлять корректные позиции сразу; ошибки остаются в очереди для повторной отправки.
5. Сборочный лист резервирует товар, но физический InventoryBalance не уменьшает. Списание выполняется при фактической упаковке.
6. Отмена до реального сборочного листа освобождает резерв в исходной ячейке. Отмена после попадания в сборочный лист и до упаковки переводит единицу в виртуальную ПРИЕМКА.
7. Нехватка товара не блокирует сборочный лист: старый заказ может быть обработан, дефицит следующих заказов показывается отдельно.
8. Добавлен Excel «Дефицит по заказам»: активные NEW/PICKING заказы, физический остаток, резерв, свободно и дефицит.
9. В открытой ячейке возле количества появились +/− для быстрого добавления/списания с выбором синхронизации WB.
10. Для всех широких table-wrap добавлен синхронный горизонтальный скролл сверху и снизу.
11. Карточка заказа открывается из локальной БД без обязательного синхронного запроса WB. Live-refresh оставлен опциональным.
12. Новый deploy_live_0_9_4.sh проверяет Python/JS до установки, делает backup, сверяет SHA256 HOST/CONTAINER и откатывает контейнер при неуспешном health-check.
