# FulfillCore 0.7.8.15 — точечный CHZ Closed Supply FIX

Устанавливается поверх 0.7.8.14 CUMULATIVE.

Исправлено только одно поведение: если WB отвечает на запись ЧЗ кодом 409, а заказ фактически находится в `supplierStatus=new` (типичный случай после закрытой/устаревшей поставки), FulfillCore теперь корректно распознаёт именно WB 409 и выполняет штатный переход `new -> confirm` через активную техническую поставку, после чего повторяет запись SGTIN один раз.

Причина ошибки: WBClient оборачивает ответ WB 409 во внутренний HTTP 502, сохраняя строку `ошибка API 409` в detail. Предыдущая проверка смотрела на `exc.status_code == 409`, поэтому ветка подготовки заказа фактически никогда не запускалась.

Также исправлено такое же распознавание 409 при замене закэшированной технической поставки, если она успела закрыться.

Не изменялись: печать, Print Agent, статусы заказов, поставки в интерфейсе, приёмка, остатки, UI и логика ручных статусов.

Логика соответствует текущему WB API: SGTIN можно записать только в `confirm`; добавление заказа в активную поставку переводит `new -> confirm`. Документация SelSup описывает эквивалентный рабочий сценарий: для заказа со старой/закрытой поставкой связь проверяется/снимается, после чего заказ можно добавить в актуальную поставку и получить этикетку.
