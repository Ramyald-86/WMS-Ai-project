FulfillCore 0.9.4.7 DB_TX_AUTO_LABEL_STABILITY

Причина зависания подтверждена снимком pg_stat_activity: десятки соединений PostgreSQL находились в state="idle in transaction", часть более 2 минут. Последние запросы были SELECT marketplace_orders. При одновременной упаковке пул соединений исчерпывался, после чего карточка заказа, сканирование и статусы получали Request timeout.

Исправлено точечно:
1. Автопечать после ЧЗ больше НЕ ждёт Wildberries внутри SQLAlchemy-сессии. WB-этикетка ждётся в фоновом worker без DB-соединения; БД открывается лишь на короткое время после фактического получения картинки для постановки одного задания Print Agent.
2. Сохраняется дедупликация: один заказ + один ЧЗ + одно рабочее место = одна автоматическая этикетка.
3. Если оператор уже сменил/удалил ЧЗ или заказ отменён, старый фоновый worker не печатает устаревшую этикетку.
4. Commercial-auth middleware закрывает свою read-only транзакцию ДО выполнения основного endpoint, а не держит её всё время запроса.
5. Для supplierStatus=complete восстановена безопасная часть старого механизма ЧЗ: один прямой set_sgtin без DB-транзакции. Если WB запрещает запись в закрытый заказ, ЧЗ остаётся сохранённым и не теряется.
6. Защитный PostgreSQL idle_in_transaction_session_timeout=45s для новых соединений (best effort), чтобы единичная будущая ошибка не могла снова положить весь сайт.

Не изменено:
- списание при упаковке;
- Stock Core v2;
- FIFO/резервирование;
- сборочные листы;
- Print Agent 1.1.7 и его токены;
- ручная печать этикетки;
- правила отменённых заказов.
