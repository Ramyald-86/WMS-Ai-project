# FulfillCore 0.7.8.39

Накопительное точечное обновление. Архив уже содержит предыдущие изменения до версии 0.7.8.38 включительно, поэтому устанавливать пропущенные версии отдельно не требуется.

## Что исправлено

- Действующий заказ WB больше не переводится в «Отменённые» из-за старого поля `status`, оставшегося в истории синхронизации.
- Для отмены используются свежие `supplierStatus` и `wbStatus`. Историческое поле применяется только к старым записям, у которых свежих статусов вообще нет.
- Перед блокировкой печати заказа с локальным статусом «Отменён» FulfillCore проверяет статус именно этого заказа в WB.
- Если WB подтверждает, что заказ действующий, ложный локальный статус автоматически восстанавливается по фактам упаковки. Упакованный заказ остаётся в «Упакованных».
- Ответ статусов другого заказа больше не может случайно примениться к открытой карточке: сверяется точный `orderId`.
- Если первый цикл получения этикетки вернул пустую проекцию, FulfillCore один раз обновляет точный статус заказа и делает финальный безопасный запрос этикетки.
- Поддерживается как обычный base64-файл WB, так и data-URI от промежуточного шлюза.
- ЧЗ, сканирование товара, правила упаковки, защита от повторной автопечати и остальные складские операции не изменены.

## Почему возникала ошибка

FulfillCore объединяет данные нескольких лент WB. В старой записи могло сохраниться поле `status=cancelled`, а свежий ответ уже содержал активные `supplierStatus/wbStatus`. Старое поле ошибочно имело тот же приоритет и при открытии карточки переводило заказ в «Отменённые». Удаление ЧЗ затем закономерно отменяло локальную упаковку и возвращало заказ в «На сборке».

## Установка

```bash
cd /opt/fulfillcore

mkdir -p backup_before_0.7.8.39
cp -a app backup_before_0.7.8.39/

unzip -o /root/FulfillCore_0.7.8.39_WB_Active_Status_Label_Print_CUMULATIVE_FIX.zip -d /opt/fulfillcore

docker compose \
  --env-file server/.env.server \
  -f docker-compose.server.yml \
  -f docker-compose.hotpatch.yml \
  restart api
```

Проверка:

```bash
sleep 10

docker compose \
  --env-file server/.env.server \
  -f docker-compose.server.yml \
  -f docker-compose.hotpatch.yml \
  exec api python -c "from app.main import app; print(app.version)"
```

Ожидаемая версия: `0.7.8.39`.

После установки нажмите `Ctrl+F5` на каждом рабочем компьютере.

## Быстрая проверка

1. Откройте в FulfillCore заказ, который в кабинете WB имеет статус «Готово к отправке».
2. Убедитесь, что он не переходит в «Отменённые».
3. Нажмите «Этикетка WB» один раз.
4. В Print Agent должна появиться ровно одна задача печати.
5. Реально отменённый в WB заказ должен остаться в «Отменённых», а печать его этикетки должна быть заблокирована.
