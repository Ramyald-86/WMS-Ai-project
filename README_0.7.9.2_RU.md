# FulfillCore 0.7.9.2 — отмена после упаковки остаётся списанной

Накопительное обновление поверх 0.7.9.1. Вся логика настоящих резервов, ПРИЕМКА, WB/ЧЗ, печати, адресного хранения, многопользовательской упаковки и Print Agent 1.2.0 сохранена.

## Изменён только один складской сценарий

- Если WB отменил заказ ДО сборочного листа — остаток не двигается.
- Если WB отменил заказ ПОСЛЕ перехода в «На сборке» (`PICKING`) — зарезервированная единица снимается с исходного адреса и перемещается в виртуальную ячейку `ПРИЕМКА`, потому что её реальное физическое место уже нельзя считать достоверным.
- Если WB отменил заказ ПОСЛЕ статуса `Упаковано` (`PACKED`) — товар **не возвращается в ПРИЕМКА и не восстанавливается на остатках**. Упаковка остаётся точкой окончательного складского списания: посылка считается исходящей и уедет на WB.
- Если упакованный отменённый заказ всё-таки физически вытащили из отгрузки, его принимают заново обычным процессом через `ПРИЕМКА`. Автоматического прихода программа не делает.

## Безопасность и совместимость

- Для новых заказов 0.7.9.1 резерв уже имеет статус `CONSUMED` после упаковки. При последующей отмене 0.7.9.2 только фиксирует аудит и оставляет этот расход без изменений.
- Для старого `PACKED`-заказа, у которого по историческим данным ещё остался активный резерв, 0.7.9.2 один раз выполняет стандартное идемпотентное списание `SHIPPING`, чтобы отмена не воскресила товар на остатках.
- Если конкретная отмена уже была обработана версией 0.7.9.1 и товар уже попал в `ПРИЕМКА`, обновление не удаляет его оттуда автоматически: физическое состояние могло уже измениться, поэтому такая единица требует обычной складской сверки/размещения.
- Повторная синхронизация одного и того же упакованного заказа не создаёт повторного списания благодаря существующему idempotency key резерва.
- Схема БД не меняется; новая миграция не требуется.

## Итоговая логика

1. `NEW` → отмена: ничего не меняем в адресном остатке.
2. `PICKING` → отмена: исходная ячейка/короб → `ПРИЕМКА`.
3. `PACKED` → отмена: товар остаётся списанным как исходящий, `ПРИЕМКА` автоматически не пополняется.
4. Физически извлечённый после упаковки товар: отдельная ручная приёмка сотрудником → `ПРИЕМКА` → размещение.
