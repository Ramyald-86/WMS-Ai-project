FulfillCore 0.9.4.5 — WB_CHZ_PRINT_STABILITY

Что исправлено точечно относительно рабочего 0.9.4.4:
- Упаковка, Stock Core v2, резервы и списания НЕ переписывались.
- ЧЗ больше не отправляется в WB вслепую: сначала live supplierStatus.
- Если FBS-заказ ещё new и уже связан с активной поставкой, он повторно добавляется в эту же поставку, чтобы WB перевёл его в confirm, после чего отправляется SGTIN.
- 409 не зацикливается: ограничены параллельность, один поток на заказ и cooldown.
- Вся сеть WB для фоновой передачи ЧЗ остаётся вне упаковочной транзакции БД.
- Карточка заказа открывается сразу по локальным данным; обновление WB идёт после открытия в фоне.
- На карточке отображается реальный режим ожидания подтверждения ЧЗ, а не ложное впечатление, что локальная упаковка не состоялась.
- На сайте публикуется Print Agent 1.1.7 SAFE SIMPLE: DIRECT TSPL, exactly-once, без Windows-службы, watchdog и Scheduled Task.
- Установщик Print Agent проверяет точную пару PACK-код + токен до включения автозапуска.
- Deploy сохраняет текущий рабочий PRINT_AGENT_TOKEN из live-контейнера в .env (значение не печатается), чтобы токен не терялся при будущем пересоздании контейнера.

Что специально НЕ менялось:
- логика резервов/Stock Core v2;
- FIFO упаковки 0.9.4.4;
- схема PostgreSQL;
- логика списания товара;
- ручной fallback передачи ЧЗ для сложных/закрытых поставок.

Rollback:
Скрипт установки сам делает backup host + live container в /tmp/fc_0_9_4_5_backup_<timestamp> и при ошибке автоматически возвращает код.
