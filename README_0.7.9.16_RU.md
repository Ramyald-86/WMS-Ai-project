# FulfillCore 0.7.9.16 — точный сборочный лист по живому остатку

Версия продолжает 0.7.9.14. Изменения 0.7.9.15 (неблокирующий ЧЗ) намеренно НЕ включены.

Исправлено:
- остатки для сборочного листа теперь выбираются строго по выбранному клиенту + физическому складу + SKU;
- общий остаток короба также считается только для выбранного клиента;
- один физический bucket `SKU + ячейка + короб` больше нельзя посчитать дважды из-за повторяющихся строк/порядка выдачи;
- новый сборочный лист больше не копирует старую ячейку из уже сформированного листа. После формирования листа товар уже списан с исходного адреса, поэтому повторное использование старого адреса было причиной «товар указан в ячейке, но его там нет»;
- при массовом формировании заказы, уже входящие в другой сборочный лист, пропускаются;
- при ручном выборе такого заказа FulfillCore выдаёт понятное предупреждение и предлагает открыть исходный лист либо штатно вернуть заказ в «Новые» перед новой сборкой;
- вручную переведённый в «На сборке» заказ без `last_picking_list_id` по-прежнему можно включить в новый сборочный лист — место для него определяется заново по текущему живому остатку.

Проверка:
`python3 tools/smoke_check_0_7_9_16.py`
