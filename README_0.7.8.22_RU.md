# FulfillCore 0.7.8.22 — WB CHZ Verified / SelSup-style flow

Точечный патч поверх 0.7.8.21. Рабочую печать, приёмку, остатки и остальные модули не переписывает.

## Что исправлено

1. ЧЗ больше не считается переданным только потому, что он сохранён локально.
2. Перед упаковкой FulfillCore теперь выполняет последовательность:
   - сохраняет точный DataMatrix за физическим заказом;
   - читает живой supplierStatus WB;
   - при необходимости освобождает только устаревшую локальную ссылку на старую поставку;
   - через официальный WB API пытается добавить заказ в активную техническую поставку;
   - ждёт supplierStatus=confirm;
   - отправляет SGTIN;
   - читает метаданные заказа обратно из WB и проверяет, что именно этот ЧЗ появился;
   - только после проверки переводит заказ в «Упаковано» и разрешает автопечать WB-этикетки.
3. Убран жёсткий предварительный запрет по списку reshipment. Теперь решение о переносе принимает сам WB API при фактическом PATCH в активную поставку.
4. Если WB не подтвердил ЧЗ:
   - код остаётся сохранён в FulfillCore;
   - заказ остаётся «На сборке»;
   - автопечать не запускается;
   - тот же DataMatrix можно отсканировать ещё раз для повторной попытки;
   - в карточке заказа есть кнопка «Передать ЧЗ в WB повторно».
5. Ручная замена ЧЗ использует тот же подтверждаемый WB-процесс.
6. Фоновая синхронизация повторяет передачу локально сохранённых ЧЗ и после успеха проверяет их через WB metadata.

## Установка

```bash
cd /opt/fulfillcore
unzip -o /root/FulfillCore_0.7.8.22_WB_CHZ_Verified_SelSup_Flow_FIX.zip -d /opt/fulfillcore

docker compose \
  --env-file server/.env.server \
  -f docker-compose.server.yml \
  -f docker-compose.hotpatch.yml \
  restart api
```

Проверка:

```bash
docker compose \
  --env-file server/.env.server \
  -f docker-compose.server.yml \
  -f docker-compose.hotpatch.yml \
  exec api python -c "from app.main import app; print(app.version)"
```

Ожидается `0.7.8.22`.
