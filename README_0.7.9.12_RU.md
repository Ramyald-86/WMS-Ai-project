# FulfillCore 0.7.9.12 — остатки только после реального сборочного листа

Точечное обновление поверх 0.7.9.11. Рабочая логика WB, ЧЗ, печати, приёмки и адресного хранения не переписывалась.

## Новое правило

- Статус `На сборке` сам по себе больше не считается фактом сборочного листа.
- Если оператор вручную перевёл заказ `Новый -> На сборке`, ячейка/короб/палета и свободный остаток не затрагиваются.
- Если WB/другая логика показала заказ как `На сборке`, но FulfillCore не создавал для него сборочный лист, остаток также не затрагивается.
- Резерв конкретной ячейки/короба создаётся только внутри фактического формирования сборочного листа FulfillCore.
- Только реальный сборочный лист записывает `last_picking_list_id` и `picking_list_generated_at`. Ручной статус больше не подделывает дату формирования листа.
- Упаковка заказа без сборочного листа разрешена, но она не списывает и не перемещает адресный остаток.
- Отмена заказа, который лишь вручную находился `На сборке` без сборочного листа, не переносит товар в `ПРИЕМКА` и вообще не трогает ячейку.
- Если сборочный лист был сформирован, сохраняется текущая надёжная схема: адрес резервируется; при упаковке резерв превращается в физическое списание; отмена до упаковки идёт по правилам резервов.

## Защита

В функции упаковки и списания добавлена серверная проверка `last_picking_list_id`. Даже если статус заказа случайно станет `PICKING/PACKED/SENT`, без реального сборочного листа операция с адресным остатком не выполняется.
