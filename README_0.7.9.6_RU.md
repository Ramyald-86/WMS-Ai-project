# FulfillCore 0.7.9.6

Гибкое адресное хранение и компактный сборочный лист без неиспользуемых колонок.

## Сборочный лист

Сборочный лист больше не имеет фиксированного набора складских колонок. Перед созданием Excel FulfillCore смотрит, какие уровни хранения реально используются в выбранных заказах, и добавляет только их.

Поддерживаемые складские колонки:

- Секция
- Палеточное место
- Палета
- Проход
- Стеллаж
- Этаж / полка
- Ячейка
- Адрес (fallback для старого/нестандартного адреса)
- Короб

Если, например, товар принят по схеме `Секция → Палета → Короб`, в сборочном листе будут именно `Секция`, `Палета`, `Короб`. Колонок `Стеллаж`, `Этаж`, `Ячейка`, `Палеточное место` не будет.

Если товар лежит по схеме `Секция → Стеллаж → Этаж → Ячейка`, появятся эти колонки, а `Палета` и `Короб` не появятся, если они не используются.

Поля товара (`Размер`, `Наименование` и т.п.) также не создаются, если они полностью пустые во всём конкретном сборочном листе. `Под 0` появляется только когда в листе действительно есть короб, который сборка забирает полностью. Колонка `✓` остаётся намеренно пустой — это рабочее поле сборщика для отметки собранной строки.

Также исправлен расчёт полного количества в коробе в ускоренном batch-пути заказов, чтобы `Под 0` корректно определялся и после оптимизаций 0.7.9.3.

## Конструктор адресного хранения

В «Адресное хранение → Массовое создание адресов» теперь можно независимо создать:

1. Стеллаж с ячейками.
2. Отдельные ячейки без стеллажа.
3. Палеточные места (`PALLET_PLACE`) — фиксированные физические места склада.
4. Палеты (`PALLET`) — прежний совместимый тип, используемый в том числе структурной Excel-приёмкой.
5. Секции / зоны (`SECTION`).

Для ячеек, стеллажей, палет и палеточных мест секция необязательна. Если её указать и такой секции ещё нет, FulfillCore создаст её автоматически и привяжет созданные адреса к ней. Проход также необязателен.

Это позволяет использовать разные реальные схемы без обязательных пустых уровней:

- `Ячейка`
- `Стеллаж → Этаж → Ячейка`
- `Секция → Ячейка`
- `Секция → Стеллаж → Этаж → Ячейка`
- `Палета → Короб`
- `Секция → Палета → Короб`
- `Палеточное место → Короб`
- `Секция → Палеточное место → Короб`

## Структурная Excel-приёмка

Формат 0.7.9.5 `Секция → Палета → Короб → Товар` сохранён без изменения исходного Excel.

При проведении новой структурной приёмки FulfillCore теперь создаёт не только палетный адрес с названием секции, но и реальный узел `SECTION`, после чего палета получает эту секцию как родителя. Коды уже существующих палет 0.7.9.5 не меняются, поэтому старые остатки и история не ломаются.

Проверка черновика заранее обнаруживает конфликт, если код будущей секции уже занят адресом другого типа.

## Совместимость

- Логика WB, Ozon, ЧЗ, резервов, отмен и печати из 0.7.9.4/0.7.9.5 сохранена.
- Существующие `CELL` и `PALLET` адреса продолжают работать.
- Существующие структурные палеты сохраняют прежние коды.
- `SECTION` является группирующим уровнем и не предлагается оператору как место, куда можно положить товар.
- `PALLET_PLACE` является обычным физическим адресом: туда можно перемещать короб/товар, резервировать остаток и получать его в сборочном листе.
