FulfillCore 0.9.1 — CRITICAL STRICT WB SKU PICKING FIX

Причина ошибки:
старый fallback мог выбрать первый SKU по артикулу, если точный штрихкод заказа не был найден локально. Для артикула с несколькими размерами это могло привязать заказ к чужому размеру и чужой ячейке.

Новая жёсткая идентификация WB-заказа:
1. точный ШК заказа;
2. альтернативный ШК только из ТОГО ЖЕ chrtId/размера карточки WB;
3. артикул + точный размер, только если найден ровно один SKU;
4. только артикул — исключительно если у артикула вообще один локальный SKU.

Если однозначного совпадения нет:
- чужой размер НЕ выбирается;
- ячейка НЕ подставляется;
- резерв НЕ создаётся;
- строка идёт как «SKU НЕ СОПОСТАВЛЕН»/«НЕ ХВАТАЕТ» до исправления справочника.

Также:
- перед каждым сборочным листом старые local_sku_id перепроверяются;
- историческая строка старого сборочного листа не переиспользуется, если размер/ШК не совпадает;
- активный старый резерв другого SKU автоматически освобождается и создаётся заново только на правильный SKU;
- сохранён fix Print Agent /result 401 из текущей 0.9.0.

После обновления ошибочный сборочный лист нужно сформировать заново. Новый лист должен показывать точный размер и ШК из заказа WB.
