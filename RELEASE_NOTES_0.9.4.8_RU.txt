FULFILLCORE 0.9.4.8 REV2 — SEQUENTIAL CONFIRMED PRINT
=====================================================
Дата: 01.09.2026
Основа: рабочая 0.9.4.7 + ТЗ FulfillCore 0.9.4.8, ревизия 2.

ГЛАВНОЕ ИЗМЕНЕНИЕ
-----------------
Вернули строгий последовательный процесс ранних рабочих версий, но без старого зависания БД:

ШК товара
 -> ЧЗ
 -> передача/подтверждение ЧЗ в Wildberries
 -> получение реальной этикетки WB
 -> постановка одной этикетки в Print Agent
 -> подтверждение фактической печати от Print Agent
 -> списание резерва
 -> статус PACKED
 -> разрешение сканировать следующий товар.

Следующий товар НИКОГДА не разрешается только потому, что фоновой поток запущен.
Разблокировка происходит только после printed=true + packed=true.

P0-1. PACKED БЕЗ СПИСАНИЯ
-------------------------
- `_consume_picking_reservation_strict(..., require=True)` теперь действительно строгий.
- `no_picking_list` и `no_reservation` блокируют упаковку с HTTP 409 и понятным текстом.
- `already_consumed` остаётся идемпотентным успешным повтором.
- создаётся событие PACKED_WITHOUT_WRITE_OFF и ERROR-лог.
- скан ШК заранее проверяет сборочный лист и активный резерв, ещё до ЧЗ.
- основной строгий путь списывает резерв только после успешной физической печати.
- добавлен диагностический GET `/marketplaces/wb/orders/packed-without-writeoff`.
- reconciliation/manual recovery оставлены require=False по ТЗ.

P0-4 / P1-2. ПОТЕРЯ ЭТИКЕТКИ
----------------------------
- старое QUEUED-задание больше не отменяется до успешного создания замены;
- сначала создаётся/flush новое задание, затем в той же транзакции отменяются более старые QUEUED;
- при отказе фонового воркера `_fc_auto_wb_label_pending` снимается и сохраняется причина;
- строгий путь повторно использует уже живое задание того же заказа/станции и не плодит дубли.

ЧЗ НЕ ДОЛЖЕН «СЛЕТАТЬ»
----------------------
- пассивная синхронизация WB больше не очищает и не заменяет физически отсканированный ЧЗ, пока строгий pack-gate активен;
- пустая/запаздывающая проекция WB не считается доказательством отсутствия ЧЗ;
- явное удаление/замена оператором и подтверждённая отмена заказа остаются рабочими механизмами.

СКОРОСТЬ WB / ЭТИКЕТКИ
----------------------
- после записи ЧЗ используются быстрые первые опросы WB, затем плавный DB-free backoff;
- как только WB подтвердил ЧЗ, этикетка запрашивается сразу;
- ожидание WB не держит SQLAlchemy Session/транзакцию;
- UI проверяет progress каждые ~250 мс;
- неизвестные программные ошибки не гоняются по длинному циклу ретраев — сразу логируются и останавливают конкретный заказ.

P0-5. ОЧЕРЕДЬ PRINT AGENT
-------------------------
- poll выбирает только ID одной самой старой QUEUED строки: SELECT ... LIMIT 1 FOR UPDATE SKIP LOCKED;
- бинарный payload поднимается отдельным db.get только для выбранного задания;
- возврат зависших CLAIMED коммитится отдельно;
- result проверяет принадлежность задания авторизованной PACK-станции;
- все payload.print_station нормализуются через normalize_station_code;
- добавляется индекс `(station_code, status, created_at)`.

P0-2. ПУЛ БД
------------
- pool_size=20, max_overflow=20, timeout=5, recycle=900 заданы штатно в create_engine;
- значения оформлены как Settings с FC_DB_* aliases;
- private QueuePool mutation удалена;
- db_pool_tuning теперь только показывает состояние;
- startup-операции разделены: сбой одной не скрывает остальные.

P0-3 / P1-5. COMMERCIAL AUTH
----------------------------
- auth-session закрывается ДО `await call_next(request)`;
- запрос больше не занимает второе соединение БД на всё время WB/packing операции;
- привязка нового клиента/склада выполняется второй короткой сессией;
- response.body_iterator безопасно пересобирается, чтобы успешный ответ не превращался в пустой.

P1-6. DISTRIBUTED LOCK
----------------------
- blocking PostgreSQL advisory lock заменён на pg_try_advisory_lock с пределом ожидания до 5 секунд;
- строгий новый путь CHZ/этикетки не выполняет WB HTTP под SQLAlchemy-транзакцией;
- legacy supply-операции дополнительно защищены этим общим timeout, но их бизнес-логику не переписывали.

P1-1 / P1-4
-----------
- старый JS background-label queue теперь разделён по PACK-станциям и делает один короткий запрос; строгий сканер вообще его не использует;
- legacy CHZ worker: 8 слотов вместо 3, нет 0.2-секундного тихого отбрасывания при коротком всплеске, старые cooldown-записи чистятся.

PRINT AGENT
-----------
Print Agent 1.1.7 SAFE SIMPLE оставлен без изменения протокола и логики печати.
Серверная версия кладёт его проверенный ZIP в `/downloads/print-agent/archive` для простой установки на новых ПК.

НЕ МЕНЯЛОСЬ
------------
- consume_marketplace_reservation / ядро Stock Core v2;
- FIFO и правила резервирования;
- формирование сборочных листов;
- правила отменённых заказов и cancel_order_to_receiving;
- ручная печать;
- протокол/токены Print Agent 1.1.7.

ДИАГНОСТИКА ПРИ УСТАНОВКЕ
-------------------------
До изменения файлов deployment сохраняет:
- состояние pg_stat_activity;
- схему marketplace_order_events;
- число PACKED без PICKING_RESERVATION_CONSUMED и период;
- статусы WB_ORDER_LABEL за 7 дней;
- число CANCELLED с причиной «Отменено 0.9.4.7»;
- DB/reliability ошибки из логов.

Реальные diff-файлы строятся с живого контейнера перед публикацией и сохраняются рядом с backup.
