FulfillCore 0.9.4.3 — PACKING FIFO STABILITY

Цель: устранить зависания упаковки и неверную блокировку старого заказа резервом.

Исправления:
1) Финальное списание зарезервированной единицы при упаковке больше не конфликтует с глобальной защитой ячейки. Резерв скрывается от guard только внутри той же незакоммиченной транзакции; другие сессии до commit по-прежнему видят ACTIVE резерв.
2) Если единственная единица была зарезервирована за более новым заказом, а оператор сканирует более старый заказ того же точного SKU, резерв безопасно переassignяется старому заказу. Новый заказ становится дефицитным. Уже начатую упаковку у другого заказа резерв не забирает.
3) Захват packing lease сделан неблокирующим: занятый/зависший заказ не держит сканер до Request timeout, FulfillCore сразу пробует следующий подходящий заказ.
4) scan-product ограничен 15 сек как дополнительная страховка. Никаких WB HTTP вызовов на этом шаге нет.
5) Сохраняется 0.9.4.2 DATABASE STABILITY. Deploy откажется устанавливаться, если её marker отсутствует.

Установка поверх 0.9.4.2:
  cd /opt/fulfillcore
  python3 - <<'PY'
import zipfile
p='/root/FulfillCore_0.9.4.3_PACKING_FIFO_STABILITY.zip'
with zipfile.ZipFile(p) as z:
    z.extractall('/opt/fulfillcore')
print('OK extracted')
PY
  chmod +x tools/deploy_live_0_9_4_3.sh
  bash tools/deploy_live_0_9_4_3.sh

Deploy берёт ИМЕННО текущие файлы работающего контейнера, делает backup HOST+CONTAINER, патчит временную копию, проверяет Python/JS, копирует на HOST+CONTAINER, сверяет SHA256, затем только перезапускает API. При ошибке — rollback.
