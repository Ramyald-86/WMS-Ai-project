# FulfillCore 0.7.9.13 — списание по сборочному листу + быстрый ЧЗ

## Исправлено резервирование/упаковка

Фактическая граница складского остатка теперь — **создание реального сборочного листа FulfillCore**.

- Ручной статус `На сборке` без сборочного листа не трогает остаток.
- При создании сборочного листа назначенная единица сразу списывается из исходной ячейки/короба.
- Резерв сохраняет точный исходный адрес как историю отбора, но имеет состояние `CONSUMED` — упаковка не пытается списать ту же единицу второй раз.
- Поэтому ошибка «Зарезервированный товар больше не числится в исходной ячейке» больше не блокирует нормальную упаковку уже отобранного товара.
- Старые `ACTIVE`-резервы автоматически совместимы: если товар уже отсутствует в исходной ячейке, FulfillCore признаёт его уже отобранным и не делает двойное списание.
- Отмена до упаковки после сборочного листа добавляет физическую единицу в виртуальную `ПРИЕМКА`, потому что исходный адрес уже не считается достоверным.
- Отмена после `PACKED` остаётся списанной, как и раньше.
- Возврат заказа в `NEW` до упаковки возвращает списанную единицу точно в исходную ячейку/короб.

## Ускорена передача ЧЗ

Раньше критический путь сканера был:

`set_sgtin WB -> немедленный GET метаданных WB -> подтверждение -> упаковка`.

Именно второй запрос мог ждать десятки секунд при медленном ответе WB, хотя сам ЧЗ уже был принят запросом записи.

Теперь путь упаковщика:

`set_sgtin WB -> успешный ответ записи -> PACKED -> печать`.

Авторитетная проверка метаданных WB остаётся и выполняется существующей фоновой сверкой. Жёсткий отказ WB на самом `set_sgtin` по-прежнему останавливает операцию.

Это убирает медленный read-back из критического пути. Если сам запрос записи WB зависает из-за WB/сети, полностью убрать это ожидание без риска ложного принятия ЧЗ нельзя.
