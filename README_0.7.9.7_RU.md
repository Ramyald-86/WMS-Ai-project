# FulfillCore 0.7.9.7

Надёжность поставок Wildberries на нескольких компьютерах и двух физических складах.

## Что исправлено

### 1. Один список поставок для всех компьютеров

Раньше каждый браузер фактически собирал список поставок заново из WB и локальных привязок заказов. Из-за выбранного в конкретном браузере склада WB, старого локального состояния или временной ошибки WB один компьютер мог видеть поставку, а другой — нет.

Теперь FulfillCore хранит центральный реестр поставок в PostgreSQL (`fc_wb_supply_registry`). WB остаётся источником истины, но последнее подтверждённое состояние поставки хранится на сервере и одинаково показывается всем рабочим местам выбранного физического склада.

Браузеры обновляют панель поставок каждые 10 секунд. Внешний список WB при этом ограничивается серверным интервалом, поэтому четыре компьютера не создают четыре одинаковых запроса одновременно.

Панель поставок больше не зависит от локально выбранного seller-warehouse фильтра конкретного браузера. Сервер сам ограничивает список текущим физическим складом FulfillCore и разрешёнными для него складами WB.

### 2. Можно создать пустую поставку

Кнопка `Создать поставку` теперь работает и без выбранных заказов.

- если отмечены новые заказы — создаётся поставка и выбранные заказы добавляются в неё;
- если ничего не отмечено — создаётся пустая поставка для текущего рабочего склада WB;
- пустая поставка немедленно записывается в центральный реестр и видна другим компьютерам.

Раньше нажатие без выбранных заказов просто завершалось без сообщения, что воспринималось как «кнопка не работает».

### 3. В существующую поставку можно добавить выбранные заказы

У каждой открытой поставки появилась кнопка `Добавить выбранные`.

FulfillCore проверяет на сервере, что выбранные заказы новые, ещё не находятся в другой поставке, относятся к одному складу WB и не смешивают несовместимый контекст.

Если ответ PATCH от WB потерялся, FulfillCore читает фактический состав поставки. Если заказы уже находятся там, операция считается успешной и повторно не создаётся новая поставка.

### 4. Создание поставки больше не «теряется» при ошибке добавления заказов

Сразу после получения `WB-GI-...` новая поставка записывается в PostgreSQL. Если WB создал поставку, но добавление заказов не подтвердилось, интерфейс показывает конкретный ID поставки и понятное предупреждение. Поставка не исчезает после обновления страницы.

### 5. Закрытие поставки стало подтверждаемым

Перед закрытием FulfillCore получает актуальный состав поставки и перепривязывает локальные заказы, если связь была потеряна.

Сохраняется прежнее складское правило: закрыть поставку можно только когда её заказы готовы к физической отгрузке по действующим правилам FulfillCore.

После PATCH `/deliver` при неоднозначной сетевой ошибке FulfillCore повторно читает список WB. Если WB уже показывает `done=true`, операция считается успешной. Это исключает ситуацию «WB закрыл, а FulfillCore показал ошибку и оператор нажал ещё раз».

Пустая поставка не закрывается — WB требует хотя бы один заказ. Интерфейс теперь показывает это явно.

### 6. Нет молчаливых кнопок

При создании, добавлении и закрытии кнопка показывает состояние `Создаём…`, `Добавляем…`, `Закрываем…`. Ошибка или результат всегда выводятся оператору. Во время операции повторное нажатие блокируется.

## Совместимость

- WB API маршруты создания и закрытия поставки остаются официальными `/api/v3/supplies` и `/api/v3/supplies/{supplyId}/deliver`.
- Добавление заказов использует уже исправленный в предыдущих версиях актуальный маршрут `/api/marketplace/v3/supplies/{supplyId}/orders`.
- Логика ЧЗ, упаковки, резервов, отмен, Print Agent, адресного хранения, структурной приёмки и сборочных листов не менялась.
- Реестр создаётся автоматически при старте API и не изменяет существующие таблицы склада.
