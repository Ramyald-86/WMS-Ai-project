FulfillCore 0.9.3 — срочный резерв FBS при появлении заказа

Что изменено:
1. Новый WB FBS заказ резервирует товар сразу при синхронизации, а не при создании сборочного листа.
2. Сопоставление остаётся строгим: точный WB ШК/размер/SKU из логики 0.9.1-0.9.2.
3. Физический товар остаётся в ячейке. Меняется только доступность: FBS_AVAILABLE -> RESERVED.
4. Обновление FBS-остатка ставится в outbox сразу после резерва.
5. Сборочный лист повторно товар не резервирует: уже существующий ACTIVE резерв переиспользуется и привязывается к листу.
6. Если новый заказ отменён до сборки, резерв освобождается обратно в FBS_AVAILABLE, а не уходит в ПРИЕМКА.
7. Если точного SKU или свободной единицы нет, чужой размер/ШК не подставляется и резерв не создаётся.
8. Сохранены fixes 0.9.1 strict SKU, 0.9.2 performance и Print Agent /result 200 compatibility.

После установки ожидаемая схема для последней единицы:
Физически на складе: 1
FBS доступно: 0
В резерве: 1

Проверка:
python3 tools/smoke_check_0_9_3.py
bash tools/deploy_live_0_9_3.sh
