# FulfillCore 0.7.8.36 — склады WB и быстрая печать после ЧЗ

Точечное накопительное обновление поверх версии `0.7.8.35`.

## Что исправлено

- Сохранённые склады WB больше не исчезают с экрана перед обновлением.
- Если API Wildberries временно не отвечает, FulfillCore возвращает сохранённый список складов вместо `Internal Server Error`.
- Неудачное обновление не очищает выбранный склад и его режим `Работа / Наблюдение / Не показывать`.
- Для нового физического склада показывается сохранённый каталог складов WB, но все позиции безопасно начинаются в режиме `Не показывать` до отдельного сохранения.
- При успешном ответе WB новый список объединяется с сохранённым: временно пропавшая из ответа строка не удаляет настройку.
- Убрано лишнее обновление статуса WB для заказов, которые уже известны как `confirm` или `complete`.
- После успешной отправки ЧЗ выполняется одна быстрая проверка вместо 12 последовательных запросов. Окончательная асинхронная проверка WB продолжается в фоне и больше не задерживает печать этикетки.
- Путь автопечати остался прежним: создаётся одна этикетка через тот же механизм, что и кнопка ручной печати; защита от дублей сохранена.
- Защита статуса сохранена: упакованный заказ не может автоматически вернуться в `На сборке`.

## Установка

### 1. Скачайте архив

Скачайте файл:

`FulfillCore_0.7.8.36_WB_Warehouses_CHZ_Fast_Print_FIX.zip`

Он должен появиться в папке `Загрузки` Windows.

### 2. Передайте архив на сервер и подключитесь

Откройте PowerShell на компьютере и выполните:

```powershell
scp "$env:USERPROFILE\Downloads\FulfillCore_0.7.8.36_WB_Warehouses_CHZ_Fast_Print_FIX.zip" root@5.129.203.223:/root/
ssh root@5.129.203.223
```

Введите пароль сервера, когда PowerShell его запросит.

### 3. Сделайте резервную копию и распакуйте обновление

После подключения к серверу выполните:

```bash
cd /opt/fulfillcore
mkdir -p backup_before_0.7.8.36
cp -a app backup_before_0.7.8.36/
unzip -o /root/FulfillCore_0.7.8.36_WB_Warehouses_CHZ_Fast_Print_FIX.zip -d /opt/fulfillcore
```

### 4. Перезапустите API

```bash
docker compose \
  --env-file server/.env.server \
  -f docker-compose.server.yml \
  -f docker-compose.hotpatch.yml \
  restart api
```

### 5. Проверьте версию

```bash
sleep 10
docker compose \
  --env-file server/.env.server \
  -f docker-compose.server.yml \
  -f docker-compose.hotpatch.yml \
  exec api python -c "from app.main import app; print(app.version)"
```

Ожидаемый результат:

```text
0.7.8.36
```

### 6. Обновите страницу

На каждом рабочем компьютере нажмите `Ctrl+F5`.

## Настройка двух физических складов

1. В верхнем поле `Склад` выберите первый физический склад, например `Реутов`.
2. В разделе `Wildberries FBS` раскройте `Склады`.
3. Для нужного склада WB выберите `Работа`, остальные переведите в `Не показывать` или `Наблюдение`.
4. Нажмите `Сохранить выбор`.
5. Сверху выберите второй физический склад, например `Мытищи`.
6. Назначьте ему собственный склад WB и снова нажмите `Сохранить выбор`.

Если во время кнопки `Обновить склады WB` Wildberries временно не ответит, сохранённые строки останутся на экране. FulfillCore покажет короткое уведомление и не сбросит выбор. Если список ещё ни разу не был сохранён, повторите обновление после восстановления WB.

## Проверка после установки

1. Переключите сверху `Реутов` и `Мытищи`: у каждого должен сохраняться собственный выбор склада WB.
2. Нажмите `Обновить склады WB`: список не должен исчезнуть, а `Internal Server Error` не должен появляться.
3. Отсканируйте ШК товара, затем ЧЗ.
4. После успешной отправки ЧЗ заказ должен перейти в `Упаковано`, а этикетка WB — один раз уйти в Print Agent.
5. Если окончательное решение WB ещё `pending`, упаковка и печать не ждут длинной серии проверок; фоновая синхронизация завершит сверку позже.

Фактическая скорость всё равно зависит от ответа Wildberries и сети, но искусственное ожидание до 12 повторных проверок в запросе упаковщика удалено.
