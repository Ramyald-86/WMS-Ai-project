# FulfillCore 0.7.8.21 — CHZ persistence + one-path auto print + order age

Точечный патч поверх 0.7.8.20.

Что исправлено:

1. ЧЗ из закрытой WB-поставки больше не стирается фоновым reconcile.
   Если WB не принимает SGTIN и FulfillCore сохраняет код локально как pending, пустой ответ WB не имеет права заменить локальный ЧЗ на None.
   Поэтому заказ остаётся с ЧЗ и не откатывается из «Упаковано» обратно в «На сборке».

2. Добавлено ручное сохранение/замена ЧЗ прямо в карточке заказа.
   FulfillCore сначала пробует передать новый код WB; если WB не разрешает из-за состояния поставки, код всё равно остаётся привязан к физическому заказу локально и помечается «ожидает передачи WB».

3. Автоматическая этикетка больше не печатается из scan-chz.
   Сервер принудительно использует единственный путь /orders/{id}/label/queue — тот же рендер, что ручная кнопка «Этикетка WB».
   После ЧЗ браузер ждёт ~1,2 секунды и запускает этот один путь.

4. Для автоматической печати добавлена серверная дедупликация на 5 минут по заказу + ЧЗ + рабочему месту.
   Перед новым auto-job отменяются старые QUEUED jobs этого заказа.

5. В таблицу автоматически добавляется колонка «Создан», а колонка времени для NEW явно показывает «в статусе Новые».
   В карточке заказа показываются время создания WB и возраст/время в «Новых».

6. В карточке и массово можно вручную назначить NEW / PICKING / PACKED / SENT.
   Для явного действия оператора разрешён локальный override даже из терминального WB-состояния; исходный статус WB по-прежнему отображается отдельно.

Важно: чтобы физически исключить повторную печать одного и того же print job при потере ACK, обновите Print Agent до 1.1.5 EXACTLY-ONCE.
