# FulfillCore 0.7.8.20 — cumulative CHZ / automatic WB label / manual workflow status

Точечный cumulative-патч для установки поверх 0.7.8.17. Отдельно 0.7.8.18 и 0.7.8.19 устанавливать не нужно.

## 1. ЧЗ для физически неотгруженного заказа в закрытой поставке

Нормальный путь не изменён: FulfillCore сначала пытается передать SGTIN/ЧЗ в Wildberries официально.

Если WB держит физически неотгруженный заказ в `supplierStatus=complete`, поставка закрыта и официальный API не разрешает вернуть заказ в `confirm` / повторную отгрузку, FulfillCore теперь не блокирует складскую упаковку:

- сохраняет точный DataMatrix за конкретным заказом локально;
- помечает передачу в WB как ожидающую (`pending WB sync`), а не как успешно принятую WB;
- переводит заказ в локальный статус `Упаковано`;
- получает и печатает уже существующую этикетку заказа WB;
- при последующих синхронизациях автоматически повторяет передачу ЧЗ, если WB снова разрешит `confirm`/reshipment.

Важно: FulfillCore не подделывает ответ WB. Если WB не принял SGTIN, интерфейс явно показывает, что код сохранён локально и ожидает передачи.

## 2. Автоматическая печать WB после ЧЗ

Ручная печать, которая уже работает правильно, оставлена без изменения.

Автоматическая печать теперь:

- не использует первый нестабильный растр сразу после сканирования ЧЗ;
- не печатает отдельным старым путём из `scan-chz`;
- после сохранения ЧЗ вызывает тот же `/label/queue`, что и ручная кнопка `Этикетка WB`;
- ждёт минимальное время стабилизации WB и проверяет два одинаковых последовательных ответа этикетки;
- затем применяет те же настройки 58×40 / поворот / масштаб / смещение, что и ручная печать.

Поле ЧЗ отправляется быстрее: debounce сканера — 180 мс. Лишний ранний запрос этикетки убран.

## 3. Ручные статусы заказа

Для активных складских статусов используется одно выпадающее поле:

- Новые
- На сборке
- Упаковано
- Отправлены

Заказ можно переводить в любой из этих статусов из любого другого активного складского статуса. Это локальная операция FulfillCore: WB и поставка не меняются.

В карточке одного заказа используется такой же единый выпадающий список.

Настоящие конечные статусы WB `Отменён` и `Получен/Продан`, а также фактические транспортные статусы WB остаются защищёнными от опасного локального отката, чтобы не создать повторную отгрузку реально уехавшего заказа.
