# FulfillCore 0.7.9.11 — устойчивый клиент/склад и быстрый интерфейс

Точечное обновление поверх 0.7.9.10. Рабочие модули приёмки, WB, ЧЗ и печати не переписывались.

## Исправлено

- Выбранные клиент и физический склад сохраняются сразу после успешного определения и восстанавливаются после перезапуска/обновления.
- При кратковременной задержке `/masterdata/clients` или `/masterdata/warehouses` интерфейс использует последний успешный локальный кэш вместо пустых селекторов.
- Серверный профиль рабочего места остаётся резервным источником контекста, но больше не может задерживать старт интерфейса надолго.
- Загрузка контекста защищена от параллельных дублей: несколько действий больше не запускают одинаковый набор тяжёлых запросов одновременно.
- История операций (до 300 последних строк) и загрузка marketplace credentials вынесены из критического пути запуска. Сканирование и складские экраны становятся доступны раньше.
- Локальные запросы FulfillCore получили короткий таймаут и автоматический повтор вместо зависания на 20–40 секунд. Долгие вызовы WB/Ozon/приёмки сохраняют увеличенный таймаут.
- При временном сбое часть данных не обнуляет выбранные клиент/склад; FulfillCore автоматически повторяет загрузку в фоне.

## Важно

Если оператор переключает физический склад, остатки предыдущего склада не показываются во время загрузки нового — это намеренная защита от работы не с тем складом.
