Изменены только:
- `app/main.py` — номер версии;
- `app/routers/marketplaces.py` — подготовка `new -> confirm` для ЧЗ и отключаемый старый автопуть печати;
- `app/static/app.js` — после успешного ЧЗ автоматическая печать идёт через тот же метод, что рабочая ручная кнопка «Этикетка WB».

Не менялись: поставки, приёмка, остатки, печать товарной этикетки, Print Agent, Реутов, ручная печать WB, создание отгрузки и остальные модули.

## ЧЗ
WB принимает SGTIN только в `supplierStatus=confirm`. Если запись ЧЗ вернула 409 и WB показывает заказ как `new`, FulfillCore теперь пытается перевести его в `confirm` через активную техническую поставку даже если локально у заказа сохранился старый `supply_id`.

Это особенно важно для заказов из старой/закрытой поставки: WB сам решает, разрешён ли перенос для повторной отгрузки. Если разрешён — заказ станет `confirm` и ЧЗ запишется. Если нет — FulfillCore покажет реальный 409 WB и не сохранит код локально.

Технические поставки теперь кешируются отдельно по складу и `cargoType`, чтобы SML/LRG не смешивались.

## Автоматическая печать после ЧЗ
Новый UI вызывает `scan-chz` с `defer_print=1`, а после успеха вызывает существующую рабочую функцию ручной печати `printWbOrderLabel()`.

То есть автоматическая и ручная печать физически используют один и тот же endpoint/геометрию. Это убирает отдельный автопуть, на котором этикетка могла растягиваться на две наклейки.

Если печать не сработала, ЧЗ остаётся закреплён, заказ остаётся упакован, и интерфейс предлагает нажать «Этикетка WB» вручную.
