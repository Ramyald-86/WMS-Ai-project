# FulfillCore 0.7.9.0 — Reliability / Multi-device

Накопительное обновление поверх 0.7.8.53. Приоритет релиза — устойчивость без переписывания уже работающих складских сценариев.

## Что изменено

- Упаковка WB теперь резервирует конкретный заказ за PACK-рабочим местом и конкретным браузерным устройством. Два компьютера не должны одновременно получить один заказ одного товара. Резерв освобождается после ЧЗ, пропуска, ручного сброса или тайм-аута.
- Критические WB-блокировки перенесены с process-local Lock на PostgreSQL advisory locks. Блокировка удерживается на отдельном физическом соединении и безопасна даже если рабочая SQLAlchemy-сессия делает commit.
- Частота синхронизации WB координируется через PostgreSQL для всех API-процессов и открытых браузеров. Браузерные интервалы сохранены ради совместимости, но они больше не умножают внешние запросы WB.
- Добавлены серверные профили рабочих мест: клиент, склад, настройки сканирования и возможности принтера. На новом браузере профиль PACK-кода используется как безопасный стартовый контекст; существующий локальный выбор не перезаписывается.
- Print Agent 1.2.0: station-bound token, устойчивый append-only журнал job_journal.ndjson, защита от повторной печати после потери ACK, TSPL/ZPL, профили 203/300 DPI, публикация профиля принтера на сервер.
- Старый Print Agent 1.1.x продолжает приниматься сервером с legacy token, поэтому обновлять все рабочие места одновременно не требуется.
- QR-этикетки ячеек через Print Agent и браузер используют один PDF-рендер 58×40. Диапазон/массовая печать через агент отправляется одним многостраничным PDF-заданием вместо сотен отдельных сетевых заданий.
- Удалён старый отдельный PNG-рендер ячеек, чтобы он случайно не вернулся в работу.
- Тайминги сканеров WB и ручной приёмки адаптируются к фактической скорости потока символов; Enter остаётся мгновенным терминатором.
- Все браузерные запросы получили timeout; безопасные GET делают один короткий retry на сетевой/502/503/504 сбой. POST автоматически не повторяется.
- Общий список системных адресов теперь включает ПРИЕМКА-ПАЛЕТЫ; логика защиты клиентов использует единый источник.
- DDL для вспомогательных таблиц перенесён из горячих запросов приёмки в стартовую additive migration. SQL-миграция приложена в app/migrations/0_7_9_0_reliability.sql.
- Приём палет/коробов защищён от гонки двух терминалов PostgreSQL transaction advisory lock + ON CONFLICT.
- Новая инфраструктура надёжности вынесена в отдельные модули app/services/runtime_reliability.py и app/routers/reliability.py. Большой рабочий marketplaces.py специально не переписывался целиком.
- В релиз добавлен tools/smoke_check_0_7_9_0.py и небольшой unit-check для ключей станций/токенов.

## Совместимость

- Существующие таблицы товара, остатков, заказов, адресов и операций не удаляются и не переписываются.
- Новые таблицы имеют префикс fc_ и создаются через CREATE TABLE IF NOT EXISTS / ADD COLUMN IF NOT EXISTS.
- Старый Print Agent 1.1.x оставлен совместимым. Возможности DPI/TSPL/ZPL, новый журнал и station-bound token появляются после обновления конкретного ПК до 1.2.0.
- localStorage остаётся резервным кэшем. Серверный профиль рабочего места добавлен поверх него, а не вместо него.
- Внешняя синхронизация WB не переведена на новый отдельный daemon в этом релизе: вместо рискованной смены рабочего механизма добавлен общий PostgreSQL throttle, который убирает stampede и сохраняет проверенный текущий цикл.

## Рекомендуемый порядок развёртывания

1. Обновить сервер до 0.7.9.0 и проверить /health/version.
2. На одном упаковочном ПК нажать Ctrl+F5 и проверить ШК → ЧЗ → WB-этикетка.
3. Проверить печать одной ячейки и диапазона через текущий агент 1.1.x — он должен продолжить работать.
4. Затем обновлять Print Agent до 1.2.0 по одному ПК, начиная с PACK-01. Для текущего XPrinter использовать TSPL / 203 dpi.
5. После каждого ПК выполнить тестовую этикетку и CHECK_BACKGROUND_AGENT.bat.

## Откат

Если проверка после развёртывания не проходит, верните каталог app из сделанной перед установкой резервной копии и перезапустите api. Новые fc_* таблицы можно оставить: старая версия их не использует.
