# FulfillCore 0.7.8.5 — Реутов / recent-first / точная диагностика заказа

Что исправлено:

1. Убрана искусственная отсечка истории WB на 100 страниц (100 000 заказов), из-за которой на крупных кабинетах свежая часть 30-дневной истории могла не попасть в FulfillCore.
2. История загружается небольшими суточными окнами, начиная с самых свежих данных.
   - обычная синхронизация: последние 3 дня;
   - «Импортировать данные WB»: полный выбранный период (до 30 дней), recent-first.
3. Склад FBS определяется строго по `warehouseId` продавца. `officeId` больше не используется как идентификатор склада: он может меняться при перепривязке склада продавца к другому складу WB.
4. «Диагностика склада» теперь показывает актуальные данные склада из GET /api/v3/warehouses: seller warehouseId, officeId, cargoType, isProcessing.
5. Если в поле «№ заказа» введён номер, «Диагностика склада» ищет именно этот заказ в WB и показывает его warehouseId, officeId, cargoType, supplyId, статусы и совпадение с выбранным складом.

Для проверки Реутова:
- выбрать Реутов;
- в поле «№ заказа» ввести `5534578341`;
- нажать «Диагностика склада»;
- затем нажать «Синхронизировать WB».

Важно по WB:
- `warehouseId` — ID склада продавца (для Реутова на предоставленном скриншоте: 2067176);
- `officeId` — физический склад WB, к которому этот склад продавца сейчас привязан;
- перепривязку `officeId` WB разрешает не чаще одного раза в сутки и нельзя выбрать офис, уже используемый другим складом продавца.
