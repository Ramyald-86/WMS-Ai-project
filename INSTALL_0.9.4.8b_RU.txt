FULFILLCORE 0.9.4.8b — FIFO PACKING EMERGENCY HOTFIX
Дата: 01.09.2026

ЦЕЛЬ ЭТОЙ ВЕРСИИ
Исправить только срочную логику упаковки WB, не переписывая рабочие ЧЗ/печать/остатки.

ЧТО ИСПРАВЛЕНО
1. Упаковка больше НЕ требует заранее существующий резерв или last_picking_list_id.
2. Для отсканированного ШК FulfillCore выбирает самый старый подходящий активный заказ WB:
   NEW + PICKING, сортировка по времени создания WB (FIFO: первый зашел -> первый вышел).
3. Резерв теперь следует за выбранным FIFO-заказом:
   - используется существующий резерв;
   - при необходимости резерв более нового нетронутого заказа переносится на старый;
   - если есть свободная физическая единица exact SKU, резерв создается автоматически;
   - если технически резерв восстановить нельзя, упаковка НЕ блокируется, а расхождение пишется в аудит.
4. Заказ NEW автоматически становится PICKING после фактического сканирования товара.
5. Если API-ключ был переподключен под тем же клиентом и это единственное активное WB-подключение,
   сканер видит заказы старого отключенного ключа. Переносится только реально отсканированный заказ,
   без массовой перезаписи истории.
6. ЧЗ -> ожидание WB -> этикетка -> Print Agent ACK -> PACKED оставлено без изменения.
   Следующий товар разрешается только после подтвержденной физической печати.
7. Print Agent 1.1.7 НЕ меняется.
8. DB, Caddy, app.js и остальные рабочие модули не переписываются.

БЕЗОПАСНОСТЬ УСТАНОВКИ
Скрипт:
- сохраняет HOST и RUNNING CONTAINER копии файлов;
- сравнивает SHA host/container, включая app/static/app.js;
- патчит временную копию фактически работающего контейнера;
- проверяет Python-синтаксис и smoke-check ДО публикации;
- копирует только main.py, marketplaces.py, stock_reservations.py;

- проверяет /health и критические FastAPI routes;
- при ошибке автоматически откатывает файлы и API.

ПРОВЕРКА В РАБОТЕ
1. Ctrl+F5 в FulfillCore.
2. Не менять Print Agent 1.1.7.
3. Взять ШК, по которому есть несколько WB-заказов.
4. Старейший NEW или На сборке должен открыться первым, даже без готового резерва.
5. Отсканировать ЧЗ.
6. Дождаться подтверждения WB и выхода этикетки.
7. Пока этикетка физически не напечатана, следующий товар должен быть заблокирован.
8. После печати — заказ PACKED и можно сканировать следующий.

ВАЖНО
Если резерв физически невозможно восстановить (например, в учете действительно нет свободной единицы),
сканирование/ЧЗ/печать теперь не блокируются. В этом редком случае FulfillCore пишет событие
PACKING_FIFO_WITHOUT_RESERVATION / PACKED_WITHOUT_WRITE_OFF для последующей сверки остатков.
Это сделано намеренно: физическая упаковка не должна останавливаться из-за технического отсутствия резерва.
